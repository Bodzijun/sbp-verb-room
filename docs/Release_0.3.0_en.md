# Verb Room 0.3.0

Verb Room 0.3.0 adds timeline azimuth keys, a per-instance position automation range that fits the room, Creative-mode motion modulation with a Path LFO, 16 `Mod Out` host output parameters, collapsible main-inspector sections, and an About dialog. Release targets are Windows x64, macOS Universal (Apple silicon and Intel), and Linux x86_64 (classic interface only).

## What is new

### Movement and sound

- **Azimuth keys on the Path timeline.** Moving paths (`points >= 2`) in **Manual** orientation gain an **Azimuth** key strip (−180…180° with shortest-arc wrapping across ±180°, `Linear`, `Ease in`, `Ease out`, `Ease in-out`, and `Hold`, up to 128 keys). Press **+ Key**, double-click the strip, click a marker for the **Angle** editor, or right-drag in **Plan** / **3D** on the selected key (or within ±0.5 % of the playhead). When keys are active in **Manual** mode, the host Azimuth/Yaw slider displays the interpolated angle read-only; switching to **Along path** or **Look at** keeps your keys stored intact. Baked late tails sample and follow keyed turns along the path without breaking XYZ velocity continuity on `Hold` jumps.
- **Position automation range that fits the room.** Under **Edit room → Scene → Automation range**, **Fit to scene** wraps all walls, zones, active source extents, listener receivers, path points, and `Look at` points with rounded margins, alongside manual X/Y/Z Min/Max boxes and **Reset (±200 m)**. A dotted box previews the active bounds in **Plan**, **Front**, and **Side** while the section is open. Changing from the `±200 m` default asks for confirmation once, a warning counts any objects outside tighter manual bounds before clamping, and **Undo** restores both bounds and coordinates in one step. Internal physics stay in metres and fitting without clamping leaves audio bit-identical and preserves baked tables.
- **Motion modulation routes (Creative mode).** Up to 64 modulation routes per instance map any source (`1..32`) or the **Listener** through 11 spatial/motion drivers (`Distance to listener`, `Distance to point`, `Azimuth to listener`, `Elevation angle`, `X`, `Y`, `Z`, `Speed`, `Radial speed`, `Path position`, `Distance to nearest wall`) and a 2–8 node shaping curve with per-segment **Smooth**, **In / Out** ranges, **Invert**, **Clamp**, and **Atk ms / Rel ms** smoothing. Targets include per-source **Source gain Δ**, **Source low-pass**, **Source high-pass**, **Source low shelf**, **Source high shelf** (same or cross-source via **Apply to**), global **Early level Δ**, **Tail level Δ**, **Wet / dry mix Δ**, and **Host output only** (`none`). Multiple routes on one target sum cleanly with 20 ms click-free transitions. Switching to **Physical** bypasses all modulation cleanly while preserving your setup.
- **Measured DSP cost:** At 48 kHz (512-sample block, 32 sources), running 64 active modulation routes measured **0.419 ms/block** vs **0.357 ms/block** with 0 routes (**+0.062 ms/block**, zero audio-thread allocations).
- **Path LFO (Creative mode).** Drawn paths include **Path LFO** (`Sine`, `Triangle`, `Saw`, `Square`, `Smooth random`, `0.05–8 Hz`, `0–100 %` depth, `0–360°` phase) modulating **Position** around the slider with a live **Swing** readout, end-of-path warnings, and a **Keep inside path** button. Path LFO follows host transport playback and leaves **Baked** late-tail tables valid.
- **Host modulation outputs (`Mod Out 1…16`).** Sixteen automatable parameters (`mo1…mo16`, **Mod Out 1** … **Mod Out 16**) are appended after the first 283 parameters so DAWs such as REAPER can link other FX parameters via **Parameter modulation / Link from FX parameter**. Assign any route's **Host out** (`1–16`), optionally with **Host output only**, to output the smoothed `0–1` curve; in **Physical** mode all slots settle smoothly to neutral `0.5`, and host write-backs on `Mod Out 1–16` are ignored.

### Interface

- **Modulation tab & optional floating editor.** The full route list, preset menu (**Add from preset…**), curve editor, and **Live telemetry** live in the **Modulation** bottom tab, with **Detach ↗** / **Mod** to open a movable/resizable floating editor over the viewport and **Dock ↙** to return it. Switching **Target** or **Driver** safely resets output ranges/curves or input ranges in one Undo step.
- **Collapsible main inspector & even bottom tabs.** All 5 bottom tabs share width evenly across desktop and narrow windows. Main-inspector sections (**Pose**, **Orientation / Azimuth keys**, **Path**, nested **Coupling**, **Path LFO**, **Host automation**, **Bake late tail**, and right-column settings) collapse cleanly with state remembered per section ID across selections and view switches.
- **About dialog.** Added **About** beside **Theme** in both Main and Edit room headers, showing the build version, release highlights, workflow tips, voluntary support links (opened via allow-listed HTTPS `app.openExternal`), copy helpers, and supporter nicknames. Pointer capture in the viewport and timeline was also hardened against lost mouse-up events.

### Presets and compatibility

- Existing projects, states, `.verbroom`, and `.txt` files continue to load unchanged. Azimuth keys, modulation routes, Path LFO settings, and non-default automation ranges are stored additively and omitted when unused/default.
- `Mod Out 1…16` are appended at parameter indices `283–298`; all first **283** APVTS parameters keep their exact IDs and indices, and the default `±200 m` (X/Y) / `0–30 m` (Z) automation range is unchanged, so existing host automation in old projects plays identically.
- With **Keep I/O** on, `.verbroom` imports union the automation range for local sources/paths, preserve `Host output only` routes and valid local source routes, and import global room routes from the preset. Moving **Manual** participants without azimuth keys still allow live azimuth rotation without dropping baked tables; when azimuth keys are active, the baked table captures the key curve.

## Known limitations

- **Analytic directivity + Save/Reload with Bake.** If an analytic source's **Directivity** (`pattern`) is changed in a session and baked, reloading the saved state/preset rebuilds the engine with a mismatched internal `fixedPattern` hash flag so the baked table loads as `Not baked` until baked once again (audio output is unaffected).
- **Web editor vs. classic UI.** Azimuth keys, the modulation matrix, Path LFO, and **Automation range / Fit to scene** UI controls are available in the web editor only; the classic UI (including Linux) continues to track an active position automation range on its sliders.
- **Viewport Path LFO display & tempo sync.** The viewport displays the base path geometry (not the instantaneous Path LFO deflection; the Path timeline highlights the oscillation swing). Path LFO rate is specified in Hz (`0.05–8 Hz`); host-tempo sync is not implemented.
- **Tables baked in 0.2.0 need one fresh Bake.** The estimator and cache changes since 0.2.1 mean 0.2.0 tables load as `notBaked`.
- **Tail direction & round-robin early reflections.** Baked late tails retain their baked orientation (or keyed azimuth curve); source directivity profiles act on direct sound and early reflections while the late tail treats sources as omnidirectional. Early reflections solve up to four sources per 128-sample control period, updating in batches over 4–6 periods with linear glide when more sources are active.
- **Host verification.** Windows 0.3.0 builds (including `Mod Out` REAPER linking) were tested in REAPER on Windows 11. A community tester tried 0.2.0 on a real Mac; versions 0.2.1–0.3.0 have not yet been tested on real macOS hardware. Linux builds and passes CI tests with the classic interface and awaits real host testing.
