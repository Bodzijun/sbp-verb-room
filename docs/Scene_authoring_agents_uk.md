# Verb Room: інструкція агенту для створення сцен

[English version](Scene_authoring_agents_en.md)

Цей документ описує поточну реалізацію 0.1.12. Перед зміною формату перевіряй код: `src/scene.hpp`, `src/rt_engine.cpp`, `plugin/SourceModel.h`, `plugin/RoomLibrary.h`, `plugin/PluginProcessor.cpp`. Не змінюй відкритий проєкт користувача в DAW або Vienna без завдання на це.

## 1. Обери формат

- **`.txt`** — текстова геометрична сцена для створення агентом, CLI та імпорту в плагін. Маршрутизація й мікшер тут не описуються.
- **`.verbroom`** — повний пресет для обміну користувачами. Налаштуй сцену в плагіні та збережи через Save room або `VerbProcessor::getRoomPresetText()`. Не вигадуй XML-параметри вручну: експортер 0.1.12 створює контейнер `VerbRoomPreset formatVersion="2"` з повним `VerbState`; формат 1 теж завантажується.
- Вбудований пресет із багатоканальними джерелами додавай через `BuiltinRoom.setup` і `loadRoomWithSetup`, а не лише текст сцени. Приклади — `orchestraRoom()` та `vslGrandHall()`.

## 2. Координати та геометрія

Одиниці: метри, градуси, секунди, децибели. X/Y — план, Z — висота. Азимут 0° спрямований уздовж +X, 90° — +Y. Вільні точки джерела зберігаються у його локальній системі: X уперед, Y ліворуч, Z вгору.

Модель підтримує вертикальні відрізки стін, горизонтальну підлогу/стелю та горизонтальні підняті платформи. Куполи, похилі площини й довільні 3D-меші не підтримуються як справжні поверхні. Фасетований план можна побудувати вертикальними стінами. Не називай горизонтальний відбивач похилою стелею.

Для закритого залу:

1. Задай простий контур без самоперетинів і дубльованих чи нульових ребер.
2. Кінець кожної зовнішньої стіни має збігатися з початком наступної, включно з останньою/першою. Внутрішні перегородки задавай окремо.
3. Джерела, усі їхні просторові точки та слухач мають бути всередині й не лежати на поверхнях. Перевіряй відступи у метрах.
4. Джерела й слухач стоять вище найвищої платформи під ними та нижче стелі/навісу. Піднята підлога має бути визначена як платформа `at`, а не лише кольорова зона.
5. Під час зміни системи координат пересувай разом стіни, зони, джерела, приймачі та слухача. Вбудовані конструктори можуть зміщувати сцену; не застосовуй це зміщення двічі.

Плагін може переорієнтовувати сцену для відображення від слухача, тому перевіряй збережений результат, а не лише початкові координати конструктора.

## 3. Синтаксис `.txt`

Рядки після `#` — коментарі. Десятковий роздільник — крапка. Назви матеріалів і джерел — один токен без пробілів; для пробілів використовуй `_`. Матеріал потрібно оголосити до посилання на нього.

```text
sr 48000
length 3.0
height 8.0
temp 20
humidity 50
order 2
rays 48000
seed 17
detect_radius 0.5
material Oak 0.10 0.08 0.08 0.10 0.12 0.15 0.18 0.25 0.65
floor Oak
ceiling Oak
wall 0 0 12 0 Oak
wall 12 0 12 20 Oak
wall 12 20 0 20 Oak
wall 0 20 0 0 Oak
listener 6 6 1.2 90
source Violins 4 15 1.4 -90 0 0 0
receiver L 5.91 6 1.2 120 0.5 0 0
receiver R 6.09 6 1.2 60 0.5 0 0
```

Повний мінімальний приклад: `docs/examples/Agent_Hall.txt`. Мінімально потрібні оголошений матеріал підлоги, `floor`, хоча б одне `source` і `receiver`. Відсутня стеля означає відкритий верх; для закритого залу завжди задавай `ceiling`.

Основні додаткові команди:

```text
# Поглинання: 7 коефіцієнтів енергії, потім розсіювання LF/HF.
material NAME a125 a250 a500 a1000 a2000 a4000 a8000 scatterLF scatterHF
# Звукоізоляція: втрати проходження, 7 значень у dB. Без transmit матеріал непрозорий.
transmit NAME TL125 TL250 TL500 TL1000 TL2000 TL4000 TL8000
# Стіна повної висоти або з явними нижньою/верхньою межами Z.
wall ax ay bx by NAME
wall ax ay bx by NAME z0 z1
# Патч матеріалу на основній підлозі / стелі.
zone floor NAME x1 y1 x2 y2 x3 y3
zone ceiling NAME x1 y1 x2 y2 x3 y3
# Платформа або горизонтальний навіс на абсолютній висоті Z.
zone floor NAME at Z x1 y1 x2 y2 x3 y3
zone ceiling NAME at Z x1 y1 x2 y2 x3 y3
# Відкритий верх: цілком або лише зона.
ceiling open
zone ceiling open x1 y1 x2 y2 x3 y3
# Інші параметри.
roughness 0.1 123
diffraction 1
clutter 12 0.4 1.6 2 10 123 0.5 1.8
```

`source` і `receiver`: `NAME x y z azimuth pattern gainDb elevationDeg`; останні чотири числа необов'язкові. `pattern`: 0 — omni, 0.5 — cardioid, 1 — figure-8. `listener`: `x y z yaw`. У плагіні вихідні приймачі створюються з Output layout і положення слухача; координати `receiver` у файлі потрібні також для CLI та не замінюють конфігурацію Output у плагіні.

## 4. Матеріали й акустика

Смуги завжди у порядку **125, 250, 500, 1000, 2000, 4000, 8000 Гц**. `alpha` — поглинута частка енергії, `tau` — передана, відбита частка `1-alpha-tau`. У кожній смузі `0 <= alpha,tau <= 1` і `alpha+tau <= 1`. `transmit` задається у dB: `tau = 10^(-TL/10)`; 0 dB означає повне проходження, а не непрозорість.

Для зовнішніх масивних стін не успадковуй ненульове `tau` від декоративного матеріалу: для кастомної непрозорої поверхні явно використовуй `tau.fill(0)` у C++ або не додавай `transmit` у `.txt`. Не змінюй поглинання лише заради кольору карти: воно змінює звук.

Використовуй `surfacePresets()` / `presetByName()` як відправну точку. Обґрунтовуй дерево, завіси, крісла, сцену та навіси. Несиметрична геометрія допустима, але матеріали симетричних за функцією поверхонь перевіряй явно. Для задньої стіни та скосів використовуй визначену групу ребер або перевірену включну межу координат. Обов'язковий тест матеріалу кожного скосу захищає від помилок `<` проти `<=`.

`length` не є виміряним RT60 і не гарантує фактичну довжину хвоста: плагін адаптує її за моделлю. Графік Decay описує модель, а не записаний звук чи точне вимірювання у конкретній точці залу. Не обіцяй відповідності реальному відомому залу без вимірювань. Перевіряй реальну імпульсну відповідь, спад по смугах та пізні підйоми.

## 5. Межі реалізації

- Плагін: до **32 джерел**, **64 просторових точок**, **64 входів**, **16 виходів**. Просторові точки рахуй через `buildPoints()`; LFE не є просторовою точкою.
- Конфігурації форматів: Mono=0, Stereo=1, LCR=2, Quad=3, 5.0=4, 5.1=5, 7.1=6, Ring=7. `firstIn` у C++ нумерується від 0, у UI — від 1. Для групи i зі стереопарою: `format=1`, `channels=2`, `firstIn=2*i`.
- `sum=true` усереднює канали в одну точку. 32 такі стереогрупи — 64 входи й 32 точки. Стерео без сумування — дві точки. Не підміняй незалежний багатоканальний матеріал моносумою без пояснення.
- До **8 піднятих платформ/навісів разом**; звичайні патчі без `at` не рахуються. Надлишкові платформи sanitizer перетворює на патчі — перевір число ДО sanitize.
- Редактор дозволяє до 128 стін, але бюджет ранніх відбиттів залежить від порядку: до 128 / 64 / 24 / 12 стін для порядків <=1 / 2 / 3 / 4. Не ускладнюй контур без перевірки фактичної моделі ранніх відбиттів.
- Поточний плагін використовує перший порядок ранніх відбиттів (`ec.erOrder=1`), решту поля формує хвіст. `order` у `.txt` стосується також автономного рендера; не обіцяй перемикання порядку ранніх відбиттів у VST лише зміною цього рядка.
- Позиційні параметри плагіна: X/Y від -200 до 200 м, Z від 0 до 30 м, азимут від -180 до 180°. Parser може прийняти ширші межі, але UI/APVTS їх не відтворять.
- Хвіст у рушії обмежений 20 с. Бюджет хвостових променів у плагіні 8000–384000; Adaptive може використати до 4× бази. Поле `rays` текстової сцени не замінює збережену Tail quality у повному пресеті.

## 6. Обов'язкова перевірка перед передачею

1. Parse → serialize → parse: геометрія, матеріали та порядок джерел збережені.
2. Перевір контур, самоперетини, матеріальні індекси, усі функціональні групи стін, позиції та висоти.
3. Перевір `firstIn + effectiveChannels() <= 64`, число точок <=64 і платформи <=8. Вхідні діапазони можуть перетинатися лише навмисно.
4. Підготуй процесор, завантаж сцену й дочекайся Ready. Порівняй джерела, точки та виходи з очікуваними.
5. Дай імпульс у першу й останню групи та в обидва канали останньої стереопари. Перевір відсутність тиші, NaN, неочікуваних повторів і різкого обриву хвоста.
6. Експортуй `.verbroom`, завантаж у чистий процесор з Keep I/O off і порівняй маршрути, мікшер, позиції, якість та вихід. Окремо перевір Keep I/O on із відмінною локальною конфігурацією.
7. Переглянь план і фронтальний вигляд. Додай читабельний опис задуму, каналів і матеріалів. Перед публікацією прибери випадкові Solo/Mute.

Корисні наявні перевірки, запускати з кореня репозиторію після збірки:

```powershell
$env:VERB_PRESETS_ONLY='1'
& './build-msvc/plugin/VerbPluginTest_artefacts/Release/VerbPluginTest.exe'
Remove-Item Env:VERB_PRESETS_ONLY
$env:VERB_VSL_HALL_ONLY='1'
& './build-msvc/plugin/VerbPluginTest_artefacts/Release/VerbPluginTest.exe'
Remove-Item Env:VERB_VSL_HALL_ONLY
$env:VERB_VSL_TAIL_ONLY='1'
& './build-msvc/tail_regression.exe'
Remove-Item Env:VERB_VSL_TAIL_ONLY
```

Новий зал повинен мати власні перевірки; успіх VSL-тесту сам по собі не перевіряє іншу сцену. Не встановлюй VST3 поверх DLL, яку використовує DAW: спочатку підготуй пакет, перевір, потім дочекайся звільнення файлу.

## 7. Організація сцени та позиційний dry (0.1.12)

Дивись [посібник редактора](Spatial_editor_0.1.12_uk.md). Назви, плоскі групи, приховування й блокування поверхонь записуються у сумісні коментарі:

```text
#@verbroom-editor-v1 wall 0 "Stage left" "Stage structure" 0 1
```

Поля: тип (`wall`, `floor-zone`, `ceiling-zone`, `floor`, `ceiling`), індекс від 0, назва в лапках, назва групи в лапках, hidden (0/1), locked (0/1). Для основних floor/ceiling індекс 0; вони не входять у переміщувані конструкції. Порожня група означає відсутність зв'язку. Усередині рядків екрануй лапки й зворотні слеші; рекомендовано зберігати через штатний serializer.

Стан шарів плану (Walls / Floors / Ceilings / Plates: 0 shown, 1 locked, 2 hidden) записується окремим рядком нового простору імен `#@verbroom-editor-v2 layers 1 0 2 0` (лише коли не всі нулі). Старі збірки (0.1.15) сприймають його як коментар. Невідомі або пошкоджені записи `v2` нова збірка ігнорує без помилки; нові види метаданих додавай лише під `v2`, бо невідомий `kind` усередині `v1` відхиляє всю сцену. Сцена без цього рядка (бібліотечна кімната, геометричний `.txt`) скидає шари до «shown».

Ці прапорці не змінюють акустику: hidden не означає відсутню стіну, locked не замінює поглинання. Не видаляй геометрію при приховуванні. Суміжні поверхні зберігають окремі матеріали; Link керує лише організацією і спільним переміщенням. Назви груп мають бути унікальними для незалежних конструкцій.

`spatialDry` — параметр плагіна, а не команда сцени. У нових екземплярах він увімкнений: прямий звук лишається позиційним, а Wet додає відбиття/хвіст без дублювання прямого тракту. Старі проєкти й пресети формату 1 зберігають попередній bypass. Для повного обміну новим режимом використовуй формат 2, не частковий XML.
