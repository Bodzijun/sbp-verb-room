# Engine E1: Size, Predelay, Stereo width, Freeze, Duck

Бодя, це опис реалізації E1. Усі шість нових параметрів додані після старих 243 APVTS IDs: порядок та діапазони старих параметрів збережено. Нативний редактор зберіг попередню розкладку; нові параметри доступні в host automation та WebView. Нативна геометрія показує авторську, немасштабовану сцену.

| ID | Значення | Default | Режим |
|---|---|---:|---|
| `size` | 50…160 % | 100 | Physical / Creative |
| `predelay` | 0…250 ms | 0 | Creative |
| `stereoWidth` | 0…200 % | 100 | Creative, крім mono |
| `freeze` | Off / On | Off | Creative |
| `duck` | 0…24 dB, 0 = Off | 0 | Creative |
| `duckRelease` | 50…2000 ms | 300 | Creative |

Physical передає нейтральні значення Creative controls; host automation продовжує зберігати overrides. Повернення в Creative відновлює їх. Web controls блокуються з поясненням; ефективні значення приходять із C++, а не обчислюються як DSP у браузері.

## Size

Рушій одержує копію геометрії, масштабовану від незмінного світового `(0,0,0)`. Масштабуються X/Y стін, нижні/верхні межі, висота залу, патчі, отвори та підняті плити; позиції джерел, усіх channel points та центр мікрофонів. Відстані між капсулами, ORTF spacing / head radius, розміри меблів і clearance, матеріали, температура та вологість зберігають фізичний розмір/значення. Clutter повторно генерується у масштабованому просторі з тим самим seed та коректно масштабованими construction anchors; розміри меблів не змінюються.

`scaleRoomGeometry` спільна з попереднім одноразовим `scaleRoom`. Старий destructive Scale room зберігає власний центр bounding box, прапорець include objects та межі висоти. Автоматизований Size не змінює авторський scene text, APVTS координати чи source spread / offsets.

Loader спостерігає значення й чекає стабільності ≥150 ms (цикл перевірки 250 ms), публікує новий immutable world і використовує наявні переходи ранніх taps та crossfade convolution IR. Worker чекає підтвердження аудіопотоком, що всі позиції вже відповідають новому Size, перед трасуванням нової геометрії. Це **перебудова на усталеному значенні**, не безперервний morph. `Rebuilding…` і requested/applied Size описують цей перехід. У статичному залі довші шляхи означають пізніші/слабші відбиття, більші втрати повітря й довший RT60; конкретний результат визначає геометрія.

Main показує ефективну геометрію та `Size 120 %`. Перетягування об'єктів у Main перераховується в авторські координати. Edit показує й редагує немасштабовану сцену з написом `Unscaled · Size 120 % applied on Main`. Energy, rays, clutter і RT60 рахуються за ефективною сценою; в Edit координати діагностичних overlays лише переводяться назад на авторський план. Energy hover зберігає ефективні метри.

## Predelay

Окрема заздалегідь виділена circular delay line затримує суму Early + Tail після їхніх рівнів, Solo та positioned wet mix. Direct та raw dry не проходять через неї. Затримка округлюється до найближчого семпла. Зміна: 20 ms лінійний crossfade між двома фіксованими read taps; поки перехід триває, запам'ятовується актуальний запит, наступний перехід бере останнє значення. Немає рухомої read head і пов'язаного pitch glide; під час crossfade можливе коротке comb забарвлення. PDC/plugin latency = 0, бо прямий тракт не затримується.

## Stereo width

Тільки reflected wet: `M=(L+R)/2`, `S=(L−R)/2`, результат `g·(M±w·S)`, де `w=percent/100`, `g=1` при `w≤1`, і `sqrt(2/(1+w²))` при `w>1`. 100 % має точний bypass; 0 % дає однаковий mono wet. При 200 % side множиться на 2 (+6.02 dB) **до** нормування −3.98 dB; сумарний приріст для чистого side обмежено +2.04 dB, а для некорельованої stereo пари зберігається RMS. Це лінійне нормування headroom, не clipping/limiter. Прямий сигнал не змінюється. Значення width лінійно доходить до цілі за щонайбільше 40 ms для повного ходу (20 ms на одиницю).

Multichannel: незалежні дзеркальні пари азимутів ±az з однаковим elevation (L/R, surrounds, rears, top-front/rear). Centre, LFE і осьові канали Ring не змінюються. Ring використовує симетрію навколо осі слухача, а не довільні сусідні пари. Stereo із двома outputs завжди одна пара. Mono позначено unavailable, ефективно 100 %, збережене значення лишається для наступного stereo layout.

## Freeze

Утримується **лише late tail**, Early і Direct продовжують реагувати на вхід. Під час утримання нове збудження convolution tail відключене, а замість її виходу звучить окремий held layer. Dry/mix, Early, source gains, Master не вимикаються. Predelay/Width/Duck продовжують обробляти reflected wet.

Метод (E2, замінює granular hold): **справжнє утримання хвоста** окремим компонентом `TailFreeze` / `DiffusingNetwork` (`src/freeze_network.hpp`). Без втрат рециркуляційна мережа з 16 ліній на кожен вихід: ортогональна матриця Адамара (FWHT ×0.25), взаємно прості затримки 45…160 ms (геометричний ряд, прості числа), вихідний вектор ±1/4. Мережі всіх каналів однакові, тож міжканальна когерентність хвоста зберігається. Під час Off у Creative записується коротка історія (≈170 ms на вихід). При engage: останні 160 ms + 10 ms стають «засівом», кожна лінія одразу відтворює свій відрізок (миттєве звучання без провалу наповнення), а на шві переходить у рециркуляцію через рівнопотужний кросфейд 10 ms (без цього розриви лишаються в петлі назавжди). Якщо засів — вільне згасання (оцінка швидкості 1/2/4 kHz відносно RT60 кімнати ≥0.2), кожна октава «розгасається» нуль-фазним банком 24 dB/oct до рівня найновішої частини. Для багатьох каналів/високих частот цей аналіз розкладається на кілька блоків (бюджет ≈20 % періоду блоку); поки він іде, грає природний хвіст, а затримку враховує сам рівень розгасання. Вихід має статичну корекцію забарвлення мережі (таблиця для 44.1/48/88.2/96/176.4/192 kHz, середнє для інших; виміряна офлайн, ≤0.7 dB). Утримання не має втрат (5 хв: дрейф 0.005 dB), новий вхід не надходить у мережу; Direct/Early продовжують працювати.

Engage — рівнопотужний кросфейд 20 ms від живого tail до held. Release: живий tail повертається за 20 ms, мережа отримує втрати, що відповідають RT60 кімнати по октавах (на лінію: 7-смуговий комплементарний банк двічі каскадом, підігнаний до ефективного затухання октави), і згасає як кімната; після 2.2×max RT60 компонент повертається в Idle. Повторне engage під час release захоплює поточний чутний хвіст (історія під час release пише held output) і кросфейдить стару мережу. Physical: компонент вимкнений (`setFreezeAvailable(false)`), історія не пишеться — нульова вартість; у Creative з Freeze Off — лише запис короткої історії. Пам'ять (мережа, історія, засів, буфер аналізу) при 48 kHz ≈1.4 MiB для stereo і ≈6.1 MiB для 16 виходів; при 192 kHz ×4 (≈24 MiB для 16). Без allocation/locks у callback. Відомі властивості: чистий утримуваний тон у будь-якій фіксованій мережі без втрат має биття (кластер мод навколо тону); на музиці це звучить як легке «мерехтіння», не як періодична грануляція. Деталі та виміри: [E2 report](../out/E2/REPORT.uk.md).

State / `.verbroom` записують `freeze=0`; завантаження примусово ставить Off навіть із чужого `freeze=1`. Audio history не зберігається. Це не скидає поточний live Freeze під час самого збереження.

## Duck

Detector — корінь суми квадратів **усіх доступних dry host inputs**, до source mapping, gain, mute і reverb. Енергетичне сумування не дає протифазним каналам взаємно скасувати detection. `target=min(1, detector/0.1)`; 0.1 FS = −20 dBFS amplitude, при цій/більшій сталiй амплітуді досягається задана кількість dB. Нижче зменшення пропорційне detector. Envelope має attack 10 ms і release `duckRelease` як часову сталу (через release лишається 1/e gain reduction). Amount змінюється окремим лінійним 20 ms ramp на повний хід 24 dB. Wet gain = `10^(−amount·envelope/20)`; 0 — точний unity після короткого amount ramp. Сталий сигнал не викликає порогового on/off pumping. Meter передає реальні dB reduction атомарно з callback.

Duck button вмикає 6 dB або останню ненульову кількість у поточній UI-сесії, повторний клік ставить 0. Amount і release — компактні sliders у Mix. У Physical обидва заблоковані; stored amount/release збережені.

## Сумісність і контракт

Нові нейтральні defaults не змінюють стару геометрію/звук. Відсутні E1 IDs у state / `.verbroom` явно отримують defaults, не успадковують налаштування попередньої кімнати. `.txt` залишається лише авторською геометрією. `.verbroom formatVersion=2` та `VerbState` містять нові APVTS `PARAM`; невідомі IDs старий parser ігнорує. Keep I/O залишає локальні Sources/Output, імпортує Size і Creative overrides разом із кімнатою. Freeze завжди Off. Новий характер пресета з E1 потребує нової реалізації для точного звучання; старий плагін лише завантажує відомі поля.

Web contract **1.2**, schemaVersion=1: capabilities стають available для п'яти функцій; нові fields effective (`sizePercent`, `sizeRequested`, `predelayMs`, `stereoWidthPercent`, `widthAvailable`, `freeze`, `duckDb`, `duckReleaseMs`, `duckReductionDb`, `lockReason`). Старі 243-field пакети лишаються валідними. Повний список тепер 249. Details і фактичні результати: [E1 report](../out/E1/REPORT.uk.md).

## Відоме performance обмеження

На поточній машині VSL 32 spatial points / 64 inputs / 12 outputs, Size160, 44.1kHz / 64, усі E1 active: середній callback ~0.824 ms, найгірший 7.611 ms за бюджету 1.451 ms, private commit ~646 MiB, C++ allocations=0. Це **перевищення реального deadline**, а не hard-real-time PASS. Налаштування буфера/маршрутизації в REAPER потрібно перевірити окремо; автоматичного обмеження чи fallback не додано. Інші остаточні тести, їхні точні команди й failures наведені у звіті, без підміни результатів.

(Історично, E1 granular — замінено в E2.) Пізнє виправлення Freeze: окремий тональний60s тест знайшов drift до3.7199dB у первісному granular варіанті. Нормалізатор зменшив максимум семи octave-centre tones до0.62268dB. Нові tonal assertions з тим самим порогом±1dB та targeted reruns описано у PROGRESS/REPORT. Лічильник phase — unsigned64-bit, без signed overflow під час тривалого hold.

(Історично, E1 granular — замінено в E2.) Freeze recapture уточнення: під час Off/release recorder пише реально чутний tail, щоб наступне engage захоплювало поточний залишок/новий матеріал. Захоплення рівня —20ms; повільний125ms envelope використовується тільки для нормування history. Повторне engage має окремий20ms crossfade старих grain heads із новим snapshot. Це прибирає підйом старого рівня на14dB та завищення швидко згасаючого IR на13dB. Standalone proof: decaying RT60=1s capture+0.7608dB, re-engage після0.5s release+0.4005dB; тести вимагають±1dB. У held On немає запису history/надходження нового input.

Експорт IR отримує Freeze Off: held audio history не є статичною імпульсною відповіддю. Duck залежить від рівня й огинаючої входу; експорт одиничного імпульсу не відтворює його дію на довільному матеріалі звичайною лінійною згорткою.

Остаточний affected Decay×3 subset (16→12,256samples):4PASS/2FAIL; shared mean89.6% (поріг70%), worst11.23ms (поріг2×5.33ms). Початковий фінальний subset пройшов38.4%/5.63ms; причину різниці не доведено. Цей результат збережений як performance failure, без послаблення тестів. Повна таблиця та resolved browser/live failures — у E1 REPORT.
